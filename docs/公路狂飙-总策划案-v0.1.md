# 公路狂飙：从外卖骑手到职业车手

## 总策划案与开发约束 v0.1

- 日期：2026-10-28。
- 本轮交付：设定、规则、经济初案、内容路线图与验收标准；不修改运行中的游戏，不生成正式资产。
- 状态：供开发者审阅的首版。用户明确要求作为设计基线；本文扩充的人名、城市名、数值、排班和关卡规模均为提案，不代表已经得到逐项确认。
- 项目定位：单人、第三人称、可探索城市、送餐生存成长与后期摩托职业竞赛。
- 一句话：王二狗揣着50元，骑表哥留下的战损9号电动车，在陌生城市送出第一份外卖，最终靠路线经验、积蓄和驾驶技术站上职业赛场。

## 1. 先立住的规矩

### 1.1 用户已明确的方向

1. 游戏名改为《公路狂飙：从外卖骑手到职业车手》。实际菜单、配置与宣传素材改名放到实施阶段，本轮不假称已完成改名。
2. 主角固定名为王二狗；开局落魄，身上只有50元。
3. 表哥借给主角一辆战损版9号电动车，来历是以前追求对象时留下的旧车。这是开场人物笑点，不做羞辱他人的核心内容。
4. 前期核心是送外卖、吃喝、找地方休息、攒钱和升级工具，不是直接选超级摩托参赛。
5. 免费住宿从桥洞、公园长椅起步，后续有更稳定的住处。
6. 游戏右下角有手机入口，打开手机里的外卖骑手App，再进入听单、抢单与接单流程。
7. 配送费每份2.50—10.00元，主要取决于距离；支持逐步成长的多单配送。
8. 必须补充真正的外卖骑手3D人物、战损电动车与城市建筑资产，不能以简陋占位模型作为正式交付。
9. 城市需有商铺、居民楼、写字楼等不同功能空间，并与现有道路、环境材质、车辆和UI风格协调。
10. 保留现有竞速作为后期内容；存款到约5万元时触发第一辆摩托车剧情，衔接职业比赛。
11. 故事是长期成长，不在一次任务或一场比赛后结束。
12. 先策划、分阶段实施，每阶段验收后再扩展。

### 1.2 本案建议的不可破坏原则

- **不是套外卖皮的原有赛车，也不是不断点击结算的放置游戏。** 前期要有真实路线选择、取送操作和生活决策。
- **现有成果不推倒重来。** 道路、赛道、摩托、骑姿、驾驶反馈与主题都是复用候选，先做回归基线再改。
- **完整城市不是无限开放建筑。** 城市道路与功能区域要连通，关键店铺和收餐点可交互；大量普通建筑只需可信外观，不承诺所有房间可进入。
- **成长不只加极速。** 路线熟悉度、承载量、续航、等待管理和住处改善都必须有价值。
- **贫穷带来选择，不制造死档。** 不能饿死删档、唯一车永久报废、随机扣光存款或强迫付费续命。
- **账本说得清。** 不把送一份餐的钱显示成几十上百元，不用隐藏补贴偷偷缩短5万元目标。
- **城市生活与赛道比赛分规则。** 城市靠稳定配送成长；职业阶段靠封闭赛事、计时和名次，不把城市横冲直撞作为唯一高收益方案。
- **先做一小片真正好玩的城市，再扩成全城。** 小地图原型不得包装成完整开放世界。
- **没有模型、动画、碰撞与实机检查，不算美术交付。** 概念图、生成预览、文件存在都不等于游戏中已可用。

## 2. 当前项目事实与转型边界

本节来自代码与本地资源检查，不是本轮运行验证。

| 项目 | 现状 | 对转型的影响 |
|---|---|---|
| 运行模式 | `.project/settings.json` 当前为单机 | 首版按单机生涯设计，不先扩成多人城市 |
| 主入口 | `scripts/main.lua`，模块化世界、仿真、UI、比赛 | 用模式协调器衔接生涯与现有竞速，避免把全部新逻辑堆进入口 |
| 地图 | `Tracks.lua:42-91` 有六张闭合赛道 | 目前不是完整城市；新城市需要路网与街区系统，不能当成现成资产 |
| 材质 | `Landscape.lua:683-778` 与 Scenic 系列着色器 | 现有路面、草土岩、水面与设施色调是对齐基线；部分UUID资源需实机确认 |
| 车辆 | `Catalog.lua:22-30` 有九辆摩托 | 复用车型ID和模型，新生涯重新定义价格与解锁条件 |
| 默认车 | `sport` 赤焰 R1000，目前免费，极速参数274 km/h | 新生涯不能继续默认拥有；购买后也不能直接按超级跑车性能当新手训练车 |
| 人物 | `Rider.lua` 已有赛车服骨骼骑手与骑姿处理 | 不是外卖骑手；不能简单换黄色就宣称新人物完成 |
| 订单 | 自由练习有导航目标 | 不是接单、取餐、送达、时限和结算系统，需要新增 |
| 存档 | `Profile.lua:5-70`，旧版金币、所有权与赛道解锁 | 没有日历、现金、生存、订单、章节、电量等字段，需新版本隔离 |
| 竞赛 | `Race.lua`、`RaceAI.lua` 等已有比赛基础 | 保留驾驶与比赛骨架；职业模式单独定义名次、积分和赛事规则 |

### 必须特别处理的旧规则

- `Profile.lua:14-28` 默认拥有 `sport`，`:36-53` 读档还会补回免费车。后续不能只把价格改成几万元而不改默认所有权。
- 旧版金币不能不经设计按1:1兑换为生涯现金，否则新角色开局50元的设定失效。
- 当前赛道解锁和奖励属于旧竞速经济，不得直接成为早期生涯刷钱入口。
- 现有世界切换主要按赛道销毁重建，不能假设天然支持大城市连续街区加载。

## 3. 玩家体验与长期章节

### 3.1 气质

烟火气、带一点自嘲的励志成长。落魄要具体：租房押金退了、工作没着落、手机只剩一点电；而不是长篇旁白堆砌悲惨经历。主角有小目标、有选择，也能在普通人的帮助下慢慢站稳。

人生赢家的含义：有稳定住处、有选择工作的自由、珍惜朋友、能承担比赛费用并赢得职业认可，不仅是资产数字越来越大。

### 3.2 章节骨架

| 章节 | 当前生活 | 主目标 | 主要新增体验 | 阶段兑现 |
|---|---|---|---|---|
| 序章：兜里五十 | 无住处、借旧车 | 吃上饭、接到第一单 | 手机、上车、取送、桥洞休息 | 第一次靠自己赚到钱 |
| 第一章：先活下来 | 桥洞与长椅 | 连续完成几个工作日 | 充电、简单整备、饭点、认识商户 | 车辆不再随时掉链子 |
| 第二章：城里的熟面孔 | 临时床位 | 稳定接单、成为熟练骑手 | 双单/三单、写字楼路线、固定商户 | 第一次拿到房门钥匙 |
| 第三章：不止是送餐 | 更稳定的收入 | 攒下购车基金 | 新城区、熟客故事、可选周排班、赛道体验 | 发现驾驶技术可以走另一条路 |
| 第四章：人生第一辆摩托 | 可用现金达到5万元 | 去车行选购、完成基础训练 | 购车、训练配置、入门赛 | 拥有第一辆摩托，而非借来的车 |
| 第五章：从新手到车手 | 送餐和训练并行 | 完成入门赛事与选拔 | 积分、车辆适配、维修、报名预算 | 获得车队试训机会 |
| 第六章：跑出自己的名字 | 职业生涯起步 | 多站比赛与稳定成绩 | 赛季、赞助、对手人物线、不同赛道 | 首个赛季冠军或重要突破 |
| 终章：路还很长 | 有住处、有朋友、有事业 | 完成主线职业目标 | 回访旧街区、感谢帮助过的人 | 冠军、生活改善与自由游玩 |

章节解锁用明确任务与里程碑，不仅判断钱够不够。允许慢慢生活，也允许专注攒钱；可选装修不能变成主线强制开销。

### 3.3 关键人物提案

- **王二狗**：普通成年青年，会骑车但没有职业比赛经验。前期穿旧外套/配送服，后期仍保留可辨认的面部特征。
- **表哥**：嘴上不靠谱，关键时刻愿意借车。旧车的“辉煌往事”用于轻松对白，不承担无限借钱功能。
- **早餐店老板**：第一个愿意耐心等主角的新商户，承担取餐教学和熟客关系。
- **老骑手**：教路线、合单和省电，不把主角一步带成车神。
- **车行师傅/前车手**：在整备和路线挑战中发现潜力，引导封闭场地训练；不无条件赠送昂贵赛车。
- **同级车手**：从不信服到彼此认可，通过多站赛事持续发展。

人物名除王二狗外均可后续确定。先做好少数反复出现的角色，不用几十个无记忆点NPC充数。

## 4. 开场到第一天的可玩脚本

### 4.1 开场表达

不要求生成视频。采用可跳过的游戏内镜头、短信和短对白。

> 王二狗翻了翻口袋，又看了眼手机余额：50.00元。  
> 表哥：“车我给你推过来了。以前这车也是有排面的，就是现在……稍微有点岁月感。”  
> 王二狗：“后视镜拿胶带粘的，也叫岁月感？”  
> 表哥：“能骑。先把今天饭钱挣出来，别的慢慢来。”

镜头落在掉漆车壳、胶带补过的座垫、旧手机支架和疲软的后减震。战损主要通过美术与温和的性能不足表达，不让新手一出门就无法完成任务。

### 4.2 首日流程与验收

1. 开场看到现金50.00元、时间、饱腹、精力、车辆电量与当前目标。
2. 表哥交车，完成上车与刹停教学。初始车有足以完成教学班次的电量和最低可用车况。
3. 引导点击**右下角手机按钮**，进入手机桌面。
4. 打开“外卖骑手”App，完成简短新手引导，选择上线听单。
5. 展示一份4—6元的保底教学单：店铺、收餐点、预计路线距离、时限、配送费清楚可见。
6. 接单，到早餐店附近停车；步行到柜台交互取餐。首单不做长时间出餐等待。
7. 按导航骑到住宅门厅/楼栋交付点，停车、下车、交付，完成结算。
8. 钱包确实增加；订单详情、余额和账本保持一致。
9. 自由再送几单，或先花钱买一份餐食。消费前显示价格和剩余现金。
10. 到桥洞或公园长椅休息，看到当日收入、支出与次日目标；保存并推进日期。

**首日版本必须从新档走通到次日，不能只展示手机界面或车模。** 教学可跳过、步骤可重试，不能因为漏点一次按钮永久卡住。

## 5. 每日核心循环

```text
起床/检查状态 → 吃饭与整备 → 手机上线
     ↓
听单/抢单 → 评估路线与容量 → 接单
     ↓
到店停车 → 取餐 → 规划多单顺序
     ↓
骑行配送 → 门厅/收餐点交付 → 逐单结算
     ↓
继续跑单 / 充电维修 / 人物事件 / 训练
     ↓
查看账本 → 选择住处 → 保存并进入次日
```

### 5.1 日历与时间提案

- 时间单位分开：现实分钟、游戏小时、游戏日，不混写。
- 前10个游戏日采用短班教学，每日主要操作约15分钟，代表约2个游戏小时的主动工作，其余时间由休息推进。
- 熟练后可自由继续逐日玩，也可使用第8节的可选排班压缩。
- 移动、取送、充电、维修与用餐消耗游戏时间；暂停菜单、阅读剧情、停稳后查看完整手机时暂停时间。
- 行驶中只看精简导航与订单提示，不弹出遮挡画面的完整手机；打开完整手机须停稳，避免既暂停计时又保留高速移动的漏洞。
- 接单后的时限按游戏时间展示，暂停时同步暂停。首日保护，正常订单给出等待和返程余量。
- 所有时间倍率统一配置；不靠给送餐倒计时单独加速制造焦虑。

## 6. 手机与配送规则

### 6.1 手机位置与功能

保持现有移动端方向、油门、刹车等关键操作习惯，右下角新增固定手机入口，但不能覆盖油门/刹车。必要时将辅助功能收进折叠菜单，并做横屏、小屏与安全区域检查。

手机桌面首版只放实际可用功能：

| App | 核心功能 |
|---|---|
| 外卖骑手 | 上下线、听单、抢单、订单、路线和日结 |
| 地图 | 商户、交付点、住处、维修、充电、车行 |
| 钱包 | 现金、收支明细、购车基金目标 |
| 消息 | 表哥、商户和剧情联系 |
| 生活 | 用餐、住宿信息与日程 |

赛事功能在剧情解锁后出现。不放大量点了没有反应的假App。

### 6.2 听单、抢单与接单的区别

- **听单**：上线后收到符合容量和区域条件的订单提示；仍需确认，默认不强制自动接受。
- **抢单**：主动浏览限时订单池，选中后申请。首版为本地模拟供给，不伪称实时真人抢单。
- **接单**：订单唯一归属玩家并占用容量；失败或过期后不能重复接取相同实例。
- **多单**：每份订单独立计费、独立计时、独立状态；系统提供顺路提示，玩家可以修改顺序。

### 6.3 订单状态机

```text
可接 → 已接待取 → 到店待出餐 → 已取配送中 → 到点待交付 → 已完成
                ↘ 取消/失败                 ↘ 取消/失败
```

- 超时先进入“迟到标记”，不瞬间把车上所有餐清空；轻微迟到影响评价或该单有限报酬。
- 取消与失败展示原因，未取餐和已取餐采用不同处理。
- 每个订单实例只能结算一次；重新进场景、保存读取、重复按交付键都不能重复赚钱。
- 存档恢复保留已取餐状态、剩余时限、交付位置及是否已经结算。
- 首版收餐点设在门厅、楼栋口、前台等位置，不用每单爬十几层楼来拖时长；后续少量特殊单再使用室内路径。

### 6.4 报酬规则提案

普通配送费：

`报价 = clamp(2.50 + 1.50 × 预计配送路程公里数, 2.50, 10.00)`

- 按可通行路网的店铺至收餐点距离计价，接单时锁定，四舍五入到分；不按直线穿楼距离报价。
- 赴店距离额外展示在订单中，玩家可据此判断是否值得接，不隐瞒空驶成本。
- 绕远、原地兜圈不提高报酬。
- 单份普通配送费始终在2.50—10.00元。初版不靠隐藏小费、无限连单奖励或随意翻倍解决经济问题。
- 一张批量商户订单如果包含多份餐，逐份列出配送费和收餐点，不把一份餐改叫“大订单”来突破上限。
- 多单合送每份只结算一次，不能同时计为路线奖励和配送费两份收入。
- 等待时间、取送点密度、返程难度参与供给平衡；长距离订单不是永远最赚，短途同路也有优势。

### 6.5 容量与等级提案

| 成长 | 同时持有订单上限 | 主要能力 |
|---|---:|---|
| 新手 | 1 | 稳定取送、认识地标 |
| 熟练 | 2 | 双单顺路、预计到达时间 |
| 老手 | 3 | 混合取送、餐品保护与返程规划 |
| 区域骨干 | 4 | 限定批次配送、复杂路线 |
| 后期专项装备 | 6，仅限合适批次 | 增加重量和停车难度，不是全场景最优 |

解锁同时要求完成量/口碑与装备，不只付钱。等级提高不把普通餐每单变成几十元。临界容量不可接入，取消释放占用；骑手暂未取到的订单也计入已承诺容量。

## 7. 生存、住处、车辆与装备

### 7.1 首版保留的状态

- 现金：统一用游戏内“元”，底层用整数“分”，不混旧金币。
- 饱腹：低值影响恢复，不快速扣生命值。
- 精力：影响长班表现与整备选择，不能让镜头摇晃到无法操作。
- 电量：路线预算、补能与回程判断。
- 车况：影响续航和轻微操控；唯一车辆始终有可恢复路径。
- 口碑：影响供给与章节，不因一单失误永久封锁主线。

首版不同时堆入口渴、疾病、复杂营养和多个重复耐久条。天气、餐品完整度作为后续扩展，待基础循环好玩后加入。

### 7.2 住处梯度提案

| 住处 | 费用提案 | 价值与限制 |
|---|---:|---|
| 桥洞 | 0元 | 最初落脚点，可存档休息；恢复较低但次日仍能工作 |
| 公园长椅 | 0元 | 更靠近部分商圈；恢复较低，不随机罚钱 |
| 基础床位 | 12元/日 | 稳定恢复、储物，作为中期经济测算基准 |
| 单间 | 450元/30日 | 更好恢复、可安排日程和车辆停放 |
| 小公寓 | 1500元/30日 | 后期生活目标与展示空间，不是成为车手的硬门槛 |

付费住处的睡眠改善不能等同每天稳定多赚几百元；房租到期提前提示，余额不足退回免费住处，不删角色或扣走唯一车辆。租期按游戏日计，不按现实离线时间收租。

### 7.3 吃喝与维修提案

- 基础餐饮预算：起步约12—14元/游戏日，成熟阶段约20元/日；具体单品构成在首日试跑后校准。
- 充电：起步短班与成熟全天工作分开定价；成熟模型按6元/工作日测算。
- 常规损耗准备金：成熟模型按0.30元/完成订单计入车辆整备账户；实际常规维修从该账户支出，不能再从现金重复扣同一笔费用。
- 特殊事故先做轻量恢复与局部订单损失，不引入无预警巨额账单。
- 电耗受实际路线、载重与车况影响，不能仅按显示订单数扣电；最终以试跑的公里消耗校准。

| 基础整备 | 80元 | 刹车与胎况恢复，减少不稳定耗电 |
| 双单配送箱 | 120元 | 满足等级条件后开放2单 |

## 8. 5万元的经济矛盾与建议解法

### 8.1 不能回避的算术

即使每份餐都付10元、完全不吃不喝，5万元也需要5000份。真实平均单价低于10元，还要生活和整备，实际会更多。

因此，不能同时承诺：低配送单价、每一单全程亲手重复、5万元现金、很短时间买车。必须在呈现方式上做选择。

### 8.2 推荐：可选周排班与明确时间快进

这是**待确认的重要设计建议**，不是用户已要求的既定系统。

- 前10日完整经历短班、生活与熟练度成长，不一开局就跳过人生。
- 熟练后玩家可自愿启用周排班，也可以继续完全手动。
- 正常模拟工作周：6个工作日，每日8个游戏小时，另休息1日；允许缩短排班。
- 玩家亲跑一个约15现实分钟、代表2游戏小时的班次；之后安排其余46个工作小时，确认收入预测与支出后推进。
- 一次周循环额外安排/结算约2现实分钟。剧情节点中断快进，不能跳过买车、搬家等关键选择。
- 后续模拟依据区域订单供给、路线、载量、工作时段与熟练度逐批生成，收入仍来自每份2.50—10.00元的配送。
- 亲跑班次只有限度影响本周效率和完成率，不能一次完美表现让此后所有订单永久满分。
- **手动班次与模拟工作时段不重叠。** 例如周总300单，亲跑12单，则模拟最多288单；亲跑收入已经入钱包，周结只能补入未结算部分。
- 模拟的全天吞吐不直接等于短班演示速度，按游戏工作时长与路线容量校准；不能把15分钟跑12单无限外推到每小时48单。
- 每周账本可展开到每天、每批与订单明细，标明“亲跑”或“排班模拟”。完成量与现金都可追溯。
- 不靠现实挂机、不无条件发钱、不强制招人抽成，也不要求看广告或付费。

### 8.3 测试版成熟经济模型

每周基本支出：

- 餐饮20元/日＋床位12元/日，7日共224元。
- 充电6元/工作日，6日共36元。
- 损耗准备金0.30元/完成订单。
- 周总支出 = 260元＋0.30元×完成量。普通维修已在准备金中，不重复扣款。

| 表现假设 | 周订单量 | 每游戏工作小时完成量 | 平均单价 | 周毛收入 | 周支出 | 周净收入 |
|---|---:|---:|---:|---:|---:|---:|
| 保守 | 240 | 5.00 | 5.80元 | 1392.00元 | 332.00元 | 1060.00元 |
| 基准 | 300 | 6.25 | 6.00元 | 1800.00元 | 350.00元 | 1450.00元 |
| 熟练 | 348 | 7.25 | 6.20元 | 2157.60元 | 364.40元 | 1793.20元 |

这些是订单供给和吞吐的测试假设，不是已验证产能，也不是每周保底收益。低评级、短排班、额外购物和高额租住会改变结果。

### 8.4 前10日与首购摩托的账面推演

- 初始50元。
- 前5日：每天8单，平均6元，短班日生活/充电/准备金合计20元，5日净余140元。
- 后5日：每天12单，平均6元，同样每日支出20元，5日净余260元。
- 基础整备与装备共350元。
- 第10日末参考现金：50＋140＋260－350＝100元。

| 路径 | 后续工作周 | 含新手期游戏天数 | 到5万元的参考现金 | 现实游玩预算 |
|---|---:|---:|---:|---|
| 熟练 | 28周 | 206日 | 50309.60元 | 约12小时 |
| 基准 | 35周 | 255日 | 50850.00元 | 约14小时 |
| 保守 | 48周 | 346日 | 50980.00元 | 约18小时 |

现实预算按：新手期约2.5小时＋每周17分钟＋约1.5小时关键剧情。额外自由驾驶、反复挑战、后续装备、较贵住房与学习成本另算。

**设计目标是首次摩托购买约12—20现实小时，不是时长承诺。** 必须先测完整班次，再决定是否保持这组数值。章节不得额外堆几十小时的强制任务却仍宣称14小时达标。

全程仍对应数千至上万份游戏内配送，但亲自操作量显著压缩。例如基准约10600份订单，其中约520份亲跑，其余明确标为排班模拟。

### 8.5 若不采用排班

保留完全手动作为可选长期玩法；不偷偷提高单价。若开发者希望主线也完全手动，则需单独决定接受更长攒钱时间，或调整5万元目标的取得方式。本文不擅自改成彩票、突然赠款、卖广告或配送团队抽成。

### 8.6 防破产规则

- 现金低于30元可获得不可出售的基础餐食、最低可用整备与充电帮助；不直接发可无限刷取的现金。
- 唯一电动车不能永久报废，救援回可工作地点，主要损失是少量时间和相关订单。
- 失败单不付报酬；额外赔扣每日合计最多为“日初现金的10%与50元中的较小值”，余额最低0元。
- 不无预警扣光整周收入；模拟负面事件先展示影响范围，不累计巨额负债。
- 排班前可看预计日结和资金风险；没钱时可换免费住处并缩短排班。
- 免费住处恢复再低也必须保留完成恢复班次的能力。

## 9. 第一辆摩托与职业衔接

### 9.1 触发、购买、参赛是三个独立步骤

1. **当前已结算可用现金达到50000元**，且送餐基础章节完成，触发一次车行邀约。累计收入、未结算订单、准备金与旧档金币不算可用现金。
2. 剧情触发后不自动扣钱、不强制切车、不锁死外卖入口。玩家可以继续存款或暂缓购买。
3. 第一辆建议复用现有 `sport` 赤焰 R1000 的外观和ID，但以“二手整备/新手训练配置”进入生涯。
4. 首购车价建议46000元；基础护具与训练整备共2000元，合计48000元。5万元购车后至少留2000元生活周转。
5. 训练采用受控输出/赛道限速配置，暂定最高120—150 km/h，最终依据实机操控测试；不能把外观车型的274 km/h参数直接当新手教学默认速度。
6. 通过训练评价后解锁正常性能和入门赛事。购车不等于职业资格，买最贵车也不能跳过技术成长。
7. 电动车保留，可回街区继续送餐；不能买摩托后把过去努力的车辆无提示删除。

### 9.2 摩托价格重排提案

所有价格是游戏平衡数值，不是现实市场报价，不按原金币简单乘倍数。

| ID | 现有名称 | 生涯建议售价 | 定位 |
|---|---|---:|---|
| sport | 赤焰 R1000 | 首购二手训练版46000元 | 第一辆摩托剧情指定候选 |
| cruiser | 远行 V1700 | 62000元 | 巡航与稳定性，非必经升级 |
| rally | 荒野 Enduro | 68000元 | 拉力与复杂路况 |
| sport_3 | 银隼 750 | 82000元 | 轻量化赛道选择 |
| cruiser_2 | 赤铜 Classic | 90000元 | 风格与巡航 |
| cruiser_3 | 暗峰 Muscle | 105000元 | 强动力巡航 |
| rally_2 | 雪脊 Trail | 112000元 | 进阶拉力 |
| sport_2 | 冰锋 RR | 128000元 | 高性能仿赛 |
| rally_3 | 沙隼 Dakar | 160000元 | 后期专项拉力 |

车型是横向选择，贵不代表全部属性更强。极速、加速、重量、维修与赛制适配单独平衡；现有目录展示值和仿真实值不一致的部分要统一，不能菜单写一种性能、实际跑另一种。

### 9.3 职业竞赛路线

- 在首购前约1—2现实小时提供一次借车封闭场地体验，让玩家提前看到后期目标；这次体验不授予车辆所有权，也不开放重复刷钱。
- 首购后：基础训练 → 新手计时 → 俱乐部入门赛 → 地区积分赛 → 车队选拔 → 多站赛季。
- 技术进度看刹车点、过弯、稳定性和名次，不仅看最高速度。
- 正式赛事按报名、训练、正赛、积分、维修组成循环；赛季有明确长度，失败可重试，不回到50元开局。
- 现有六张赛道作为职业内容库逐步接入，不能简单沿用旧金币解锁价。
- 奖金量级随阶段提升，但要同时公布报名/整备预算；职业阶段不能继续靠一场几十元奖励支撑十万元级车辆。
- 赛事奖励数值在竞赛阶段另出专项表，不在本轮伪造一个尚未试跑的完整赛季经济。
- 正式生涯使用竞赛名次、检查点和积分规则；旧版特殊追逐/淘汰逻辑不直接混入职业主线。

## 10. 城市：最终目标与分期建设

### 10.1 整体结构提案

城市暂名“临湾市”。参考GTA的是连通城市、生活节奏、车辆与任务一体化，不复制具体地图、角色或剧情，也不把完整大城市误解为所有建筑都可进入。

```text
                   近郊公路 / 现有赛道入口
                              │
  老居民区 ── 商业街 ── 商务中心 ── 河滨公园
      │           │           │          │
  桥下落脚点 ─ 城市主干道 ─ 新住宅区 ─ 河岸道路
                  │           │
               仓储片区 ─ 车行/维修/训练场
```

- 最终研究目标约3 km×3 km的连续城市空间，不代表当前引擎预算和内容产能已经验证。
- 先制作可密集反复配送的生活区，再扩住宅、商圈、商务区和近郊连接。
- 城市道路按真实米制和车辆比例设计，路口、路肩、停车点、巷道服务实际玩法。
- 现有赛道地理线形与材质基线保留，城市通过近郊道路和明确场景入口衔接。首版允许过渡加载，不为“无缝”牺牲稳定性。

### 10.2 不同区域必须有不同玩法

| 区域 | 主要资产 | 配送差异 |
|---|---|---|
| 老街/餐饮街 | 门店、招牌、雨棚、后厨入口、街边停车 | 店铺密集、短途、易合单 |
| 旧住宅区 | 多层住宅、院门、门厅、楼栋号 | 巷路与交付点辨识 |
| 商务区 | 写字楼、前台、广场、车库口 | 饭点密集、同楼批量、交付等待 |
| 新住宅区 | 小区、步行道、分栋入口 | 门口至楼栋的最后一段路线 |
| 河滨公园/桥下 | 桥体、步道、长椅、照明 | 免费住宿、人物剧情、生活地标 |
| 仓储近郊 | 仓库、维修店、充电点、车行 | 长距离路线与转职业剧情 |

### 10.3 第一块城市切片

- 初始约400 m×400 m，做密度和美术验证，不称为全城。
- 至少5家不同外观的可取餐商户、10个明确交付点、桥洞/长椅2种免费休息点、1个充电点、1个维修点。
- 至少一个环路和两条有意义的连接/捷径，不是只有一条走廊来回跑。
- 抽取不同店铺、目的地、时间窗形成订单；不能把25个同位置换名字当25个地点。
- 首版至少有可辨识的商铺、居民楼与写字楼外观样板；关键店铺和交付处有必要局部内景。
- 先验证电动车低速操控和最后几十米的取送体验，再扩城区；不先铺满几平方公里空楼。

### 10.4 城市技术底线

- 道路图和视觉道路一致，导航不能穿墙、跨河或引导到未连通台阶。
- 静态碰撞、可驾驶路面和交互触发范围分开，实施前绘制碰撞示意与擦边测试。
- 支持步行、上车、下车与车辆停靠；建筑、车体、人物碰撞尺度一致。
- 中远景用LOD、实例化、遮挡与分区预算，不一次加载所有高细节建筑。
- 行人与交通先做少量可靠行为，再提高密度，不能在取餐门口无限刷车堵死玩家。
- 性能目标建议移动设备稳定30 FPS、桌面尽量60 FPS；必须记录测试设备、分辨率、加载耗时与内存，不能拿桌面截图替代移动验收。

## 11. 美术与3D资产规范

### 11.1 与现有内容对齐

- 以现有道路/环境的PBR质感、车辆尺度、日光明暗和地形配色为基础，新增城市采用克制写实，不突然换成纯色积木或夸张卡通。
- 旧车的陈旧通过粗糙度、磨损、刮擦、污迹和部件状态表达，不通过低面数和贴图模糊表达。
- UI沿用 `RacingTheme.lua` 的深灰、钢灰、琥珀和青色层次；生活提示可用温暖辅色，但不能整套变成无关的彩色手机小游戏。
- 当前车库背景图是视觉参考，不是三维车库已完成的证据；现有环境的部分纹理解析也需实机确认。

### 11.2 王二狗与骑手资产

- 明确成年，正常人体比例，可辨认面部、手部、鞋、衣褶与装备细节。
- 至少支持便装/配送服/赛车服三个阶段，优先共享身份特征和兼容骨架，不能后期变成另一个人。
- 动作需求：待机、走路、跑步、上车、下车、骑姿、取餐、交付、看手机；先覆盖首日所需最小集。
- 骑行手脚与车把、脚踏对齐，服装不大面积穿车；盒装餐/手持手机独立挂点，不与人物身体永久焊死。
- 当前赛车骨架和IK可评估复用，但外卖人物必须完成姿态与比例适配，不能只换纹理。

### 11.3 战损9号电动车资产

- 项目内称“9号电动车”，本案先作为剧情车型命名，不默认复制现实品牌标识或宣称联名。
- 必须有完整车架、踏板、座垫、前叉、双轮、车把、灯具、后视镜、电池空间与载物结构。
- 战损特征：一侧外壳刮伤、补过的座垫、胶带固定的非关键外饰、旧支架；关键部件保持能合理工作。
- 车轮能独立旋转，前叉/车把能转向，灯具和配送箱可独立控制；模型交付时检查轴心与局部朝向。
- 作为城市电动车独立调参，起步极速提案约35—40 km/h，续航提案约35—50 km；最终以城市场景驾驶和路线长度校准。
- 不能直接套274 km/h摩托的动力，不能用一个长方体加两个圆当正式车模。
- 修复升级尽量能在外观上看见；原始战损状态保留用于剧情回忆和对比。

### 11.4 建筑资产

- 第一批：餐饮店模块、便利店、住宅模块、办公楼模块、桥洞与桥体、车行/维修店、充电点、街道小物。
- 模块化不等于统一贴同一张墙：入口、窗、招牌、空调、栏杆、雨棚和屋顶轮廓需要组合变化。
- 建筑必须有可信尺度、门窗厚度、基础材质和必要碰撞；不接受所有立面都是平面贴图的近景交互点。
- 首批近景资产质量优先于铺城面积，远景可简化但不能在正常驾驶距离突然换形或消失。

### 11.5 资产制作与验收流程

```text
风格参考/尺寸规范
  → 骑手与电动车概念预览
  → 开发者选定方向
  → 独立生成/制作人物、车辆、箱体、建筑模块
  → 骨架/分件/材质/碰撞适配
  → 城市切片实机截图与驾驶检查
  → 验收后批量扩展
```

- 人物、电动车、配送箱和手持道具分别作为可复用资产处理，不一张图生成后指望所有部件都可动。
- 重要人物与主车使用先预览再确认的流程；预览不满意不进入批量高质量制作。
- 资产预算在第一批实测后确定，记录三角面、材质数、贴图大小、骨骼数与加载时间；不是面数越多越好。
- 必须提供轮廓检查、近景细节、驾驶相机尺度与移动端运行结果。坏UV、贴图缺失、轮胎不转、握把错位都属于未通过。
- 占位只允许内部灰盒阶段，标明状态，不能作为用户要求的正式美术交付。

## 12. 代码、模式与存档约束

### 12.1 建议模块边界

后续按现有模块风格渐进加入，命名可在实施时微调。

| 模块组 | 职责 |
|---|---|
| Career/Story | 章节、人物消息、一次性剧情与门槛 |
| Career/Clock | 游戏日历、时间倍率、暂停与时间推进 |
| Career/Wallet | 整数分账本、支出、准备金、唯一结算 |
| Career/Needs | 饱腹、精力、住宿与恢复 |
| Delivery | 供给、订单状态、时限、容量、评价与导航 |
| City | 路网、街区、商户、收餐点、交互与分区 |
| Character | 步行、上/下车、动画与挂点 |
| Phone | 手机桌面、骑手App、地图、钱包与消息 |
| Vehicles | 电动车、电池、车况、装备与摩托适配 |
| Career/Schedule | 可选周排班和模拟账本，仅确认采用后开发 |

不把生涯、订单、城市和手机全部写进 `main.lua` 或单个HUD大文件。单文件超过1500行必须拆分；已有大模块先明确边界，按实际改动逐步提取，不做无关全量重构。

### 12.2 三种进度隔离

- **新生涯**：王二狗、50元、借电动车、没有摩托所有权。
- **旧版竞速存档**：保留旧车辆、金币与赛道，不清档、不自动折算成新生涯财富。
- **独立练习/旧版入口**：可保留现有竞速供回归与体验，但收益不进入生涯；界面明确标注，不能当成新手绕过成长的赚钱入口。

首版默认引导新生涯；旧玩家在独立入口访问旧进度。迁移和重置必须先备份并显式选择，不能静默覆盖。

### 12.3 生涯存档最小字段

版本、主角身份、现金分、准备金分、日历时间、当前住处/租期、生存状态、借用/拥有车辆、电池/车况、装备、等级/口碑、活动订单、已结算订单去重信息、章节与剧情标记、城市交互进度、赛事资格/积分，以及排班状态。

- 金钱、所有权、订单状态和剧情触发必须保持一致；保存失败不能既扣钱又丢车，或既发钱又保留未交付订单。
- 场景切换不清空已接订单；不允许重复加载刷一遍结算。
- 到5万元的剧情只触发一次，但买车前仍重新检查当前余额。
- 退出/异常恢复时保留合法订单状态，不通过重载重置倒计时或复制餐品。
- 需设计账号持久化。引擎文档明确WASM本地文件刷新可能丢失，不能仅凭旧本地Profile宣称生涯已可靠保存；正式版评估账号云端快照、失败提示与本地回退。
- 云端保存确认前界面不得显示“已云存档”；首次接入时另读相关接口并测试跨会话恢复。

## 13. 分阶段执行与验收门槛

### P0：策划与基线冻结（本轮）

交付本文，明确必保设定、建议项、经济取舍、美术标准与阶段顺序。只新增策划文档，不改变当前可运行版本。

**通过条件**：确认总体方向，尤其是可选排班与首购方案；不是要求一次确认所有几十项小数值。

### P1：主角与电动车视觉定稿、城市灰盒

- 王二狗配送形象、9号战损车出预览，确认后做可用资产。
- 建立风格与尺寸对照，测试现有材质在城市中的匹配。
- 制作第一块400 m×400 m路网灰盒和近景样板，验证步行/骑行/停车/上车下车。
- 定义生涯存档与旧档隔离，准备回归检查。

**通过条件**：人物与主车形象获得确认；车轮、骑姿、碰撞和道路连通可用；有近景材质样板。此时仍不叫完整首日版本。

### P2：第一天纵向切片

- 新档50元、开场、右下角手机、骑手App、第一单到日结。
- 饭、免费住处、充电和基础整备可用。
- 首日涉及资产使用验收过的正式近景资源，不以灰盒替代最终效果。

**通过条件**：从新档完整玩至次日；至少覆盖接单→取餐→送达→到账→吃饭→睡觉→读档恢复，所有金额对账；断点重进不刷钱，失败可恢复。

### P3：前期生涯与多单成长

- 跑通前10日，增加双单/三单、装备、床位、口碑与人物线。
- 实测订单吞吐、迷路比例、等待时间、生活开销和失败损失。
- 若采用周排班，在这一阶段末做小规模经济试验，不先批量写长期剧情。

**通过条件**：连续多个游戏日可玩，成长明显，穷困仍有恢复路径；经济账本可复算；亲跑和模拟不会重复计账。

### P4：城市扩区与5万元中期主线

- 扩展商务区、新住宅区、近郊与车行，增加区域差异。
- 加入约每4—6游戏周一次的关键事件，避免排班变成机械点按钮。
- 进行性能与加载预算检查，决定最终城市规模。
- 做短测与长测，验证12—20小时首购目标，而不是凭公式宣布完成。

**通过条件**：城市功能连通、关键建筑与玩法有差异，达到5万元触发正确；不能把只有城市外围轮廓的地图当完整成品。

### P5：第一辆摩托与职业入门

- 购车剧情、训练配置、护具、初级计时与正式参赛。
- 调整旧车型价格、默认所有权、赛事奖励和解锁规则。
- 复用现有赛道，保留原驾驶特色但隔离新旧经济。

**通过条件**：从骑手到车手有完整过程，首购不扣光生活费；比赛可以输、可重试、积分与收益正确保存。

### P6：长线职业与结局

- 多站赛季、车队人物、车型横向选择、赞助与生活改善。
- 扩展天气、城市交通/行人与少量特殊配送，而非首版全塞。
- 终章回访、自由游玩和长期存档回归。

**通过条件**：主线有收束，不只解锁最后一辆车后突然结束；旧街区和送餐身份仍有叙事意义。

## 14. 每轮开发的统一验收清单

### 功能

- 新档、继续、旧档入口、返回主菜单、场景切换正常。
- 手机不覆盖关键驾驶键；鼠标和触屏均可操作。
- 首单/多单状态、容量、时间、取消、迟到、结算和读档一致。
- 金钱整数分存储、显示到分，所有收支可解释。
- 低现金、没电、体力不足、模型加载失败都有恢复或明确错误提示。

### 美术与驾驶

- 骑手比例、车轮/车把轴心、手脚挂点、动作过渡、近景材质正常。
- 住宅、写字楼、店铺有区别；取餐/收餐交互处不是无门无窗的方块。
- 新旧道路拼接、光照、接地、碰撞和导航一致。
- 电动车低速操作不是摩托仿真的简单缩小倍率。

### 工程

- 修改Lua前阅读对应文档与至少3个相关示例，基于现有模块/合适脚手架实施，不凭记忆猜API。
- 使用新UI系统；若使用raw NanoVG，先确定分辨率模式。
- 所有代码改动后先LSP错误诊断，再调用官方构建，之后预览/运行验证。
- 不写入dist，不改只读库，不自建预览服务。
- 首轮保留有用日志，确认稳定后清理；不得每帧大量刷屏。
- 不用“构建成功”替代功能/性能验收，也不把静态检查称为实机通过。

## 15. 本轮建议确认的重点

1. **核心定位**：前期城市送餐生存，中期攒钱改善生活，后期现有摩托竞速转职业生涯。
2. **时间压缩**：是否采用熟练后自愿开启的“亲跑代表班次＋周排班模拟”，解决低单价与5万元的重复劳动矛盾。推荐采用，保留完全手动模式。
3. **第一辆摩托**：5万元是当前可用现金触发门槛；建议首车46000元＋护具/训练整备2000元，保留至少2000元，不自动扣款。
4. **先做什么**：先定王二狗、战损电动车与街区样板，再交付完整第一天；不先造一个空旷大城市，也不先写几十章不可玩的剧情。

除这些关键选择外，具体数值先按测试提案推进，依据首日与前10日试跑数据调整，保留每次调整的理由与影响范围。

**本轮完成边界：策划文档已建立。游戏内改名、模型生成、城市搭建与玩法改造均尚未实施，不把规划写成已完成内容。**
